# Runtime observation gets its own outbound socket

fmx exposes Observer state and optional attributed ADE activity on a third, mode-0600 Home socket (`/tmp/fmx-<uid>-<home id>.obs`) instead of reusing ADE ingress or control request/reply, because a slow outbound reader must be unable to delay either Fx lifecycle delivery or Runtime commands. Each connection begins with a complete authoritative state snapshot, subsequent state is complete and deduplicated, and Home-wide activity remains self-attributed, live-only, and gap-aware rather than server-scoped or replayed; per-Observer queues are bounded and raw ADE payloads require an explicit subscription. The socket exists only with the Runtime, starts after restored metadata is ready, and Observers neither count as terminal Clients nor keep the Runtime alive.
